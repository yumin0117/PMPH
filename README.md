### 환경 카메라 YOLO 적용의 역할 구분

프로젝트는 환경 카메라 영상에도 YOLO 객체 탐지를 적용하는 구성으로 변경했습니다. 담당 범위는 다음과 같이 구분합니다.

| 구분 | 담당 범위 |
|---|---|
| 본인 | YOLO 공통 객체 탐지 코드 작성·제공 |
| 본인 | USB 환경 카메라 연결·영상 수집·영상 URL 제공 코드 작성·제공 |
| 서버 담당 팀원 | 환경 카메라 프레임에 YOLO 패키지·탐지 코드를 연결하고 통합 실행 흐름에 반영 |

`pc_environment_camera.py` 자체에는 YOLO 모델 호출이나 추론 코드가 포함되어 있지 않습니다. 이 문서의 본인 수행 내역은 **YOLO 코드 제공과 환경 카메라 연결 코드 제공**까지이며, 환경 카메라의 실제 YOLO 연결 구현은 팀원 담당으로 구분합니다.

## 🔵 주요 기능

### 로봇 주행 조작

다음 6가지 방향의 조작 입력을 지원합니다.

- 전진
- 후진
- 좌회전
- 우회전
- 후진 좌회전
- 후진 우회전

PC에서는 방향키와 마우스 버튼을 사용하고, 모바일에서는 원형 조이스틱을 사용합니다. 조작 입력을 해제하면 정지 요청이 발생하도록 구성했습니다.

`start_move()`와 `stop_move()`는 PC GUI의 이동 시작·정지 입력을 처리하며, `resolve_keyboard_direction()`은 여러 방향키의 조합을 해석합니다.

### PC GUI

Tkinter를 이용해 다음 화면을 구성했습니다.

- 로봇 카메라 영상 표시
- 환경 카메라 표시 영역
- 주행 버튼과 키보드 조작
- 현재 이동 방향·속도·연결 상태 표시
- 집게 잡기·놓기 조작
- 후레시 ON·자동 모드 조작
- 로봇 카메라 전체화면
- 음성·텍스트 명령 입력창
- 명령 처리 상태·결과·오류 표시

## 🔵 YOLO 객체 탐지 코드

`YOLO_detector.py`의 `YOLODetector`는 입력받은 카메라 프레임에 객체 탐지를 수행하는 공통 모듈입니다.

### 구현 내용

- Ultralytics YOLO 모델 로딩
- 입력 프레임 추론
- 탐지 박스 좌표 추출
- 모델의 클래스 이름 조회
- 객체별 신뢰도 표시
- Bounding Box 및 탐지 수 표시
- 지정한 프레임 간격으로 추론
- 추론하지 않는 프레임에서 최근 탐지 결과 표시

### 모듈의 기본 설정

```python
model_path = "yolov8n.pt"
confidence = 0.35
imgsz = 256
detect_every_n_frames = 5
```

위 값은 `YOLODetector` 생성자의 기본 인자입니다. 사용하는 코드에서 다른 값을 전달하면 해당 값이 적용됩니다.

탐지 클래스 이름은 `self.model.names`에서 읽습니다. 실제 탐지 대상은 사용하는 모델 파일에 따라 결정됩니다.

### 주요 함수

| 함수 | 역할 |
|---|---|
| `YOLODetector.__init__()` | 모델과 추론 설정 준비 |
| `_run_inference()` | 객체 추론 및 좌표·클래스명·신뢰도 추출 |
| `_draw_detections()` | 박스·이름·신뢰도·탐지 수 표시 |
| `detect_and_draw()` | 추론 주기 관리와 결과 표시 |

본인 작업은 **YOLO를 활용하는 탐지 코드와 시각화 코드 작성·제공**입니다. 이 모듈 자체는 데이터셋을 구성하거나 모델을 학습하는 코드가 아닙니다.

## 🔵 환경 카메라 연결

`pc_environment_camera.py`는 컴퓨터·노트북에 연결된 USB 환경 카메라 영상을 읽어 다른 화면에서 사용할 수 있도록 제공하는 프로그램입니다.

### 처리 과정

1. 카메라 번호와 백엔드 설정으로 USB 카메라를 엽니다.
2. `capture()`에서 프레임을 반복해서 읽습니다.
3. OpenCV로 프레임을 JPEG로 변환합니다.
4. `Frames`에 최신 JPEG와 프레임 순번을 보관합니다.
5. 영상 URL과 단일 이미지 URL을 통해 프레임을 제공합니다.
6. 종료 시 카메라와 실행 자원을 정리합니다.

### 주요 클래스와 함수

| 클래스 / 함수 | 역할 |
|---|---|
| `Frames` | 최신 JPEG·프레임 순번·오류·종료 상태 보관 |
| `Frames.publish()` | 새 프레임 저장 및 대기 작업 알림 |
| `Frames.wait()` | 이전 순번 이후의 새 프레임 대기 |
| `Frames.stop()` | 종료 상태 전달 |
| `capture()` | 카메라 프레임 읽기·JPEG 변환·갱신 간격 조정 |
| `make_handler()` | 영상 확인·MJPEG·단일 이미지 요청 처리 구성 |
| `main()` | 실행 옵션 해석·카메라 준비·종료 처리 |

### 현재 코드 설정

| 항목 | 기본 설정 |
|---|---|
| 카메라 번호 | `0` |
| 요청 해상도 | `640 × 360` |
| 프레임 처리 목표 | `10 FPS` |
| JPEG 품질 | `80` |
| 출력 포트 | `8081` |
| 연속 영상 | `/video_feed` |
| 단일 이미지 | `/snapshot.jpg` |

해상도는 카메라 장치에 요청하는 값이며, 실제 적용 여부는 장치와 드라이버에 따라 달라질 수 있습니다.

### 실행 옵션

| 옵션 | 기능 |
|---|---|
| `--camera` | 카메라 번호 선택 |
| `--port` | 영상 제공 포트 지정 |
| `--fps` | 프레임 처리 목표 지정: 1~30 |
| `--backend auto` | 운영체제에 맞는 기본 백엔드 사용 |
| `--backend dshow` | Windows DirectShow 사용 |
| `--backend msmf` | Windows Media Foundation 사용 |

Windows의 `auto` 설정은 DirectShow를 사용하고, 그 외 환경에서는 OpenCV의 기본 백엔드를 사용합니다.

### 컴퓨터·노트북에서 실행

파일을 저장한 폴더에서 실행합니다.

```powershell
py -m pip install opencv-python
py pc_environment_camera.py
```

다른 카메라가 선택되면 카메라 번호를 변경합니다.

```powershell
py pc_environment_camera.py --camera 1
```

Windows에서 카메라 연결 방식 변경이 필요한 경우:

```powershell
py pc_environment_camera.py --camera 0 --backend msmf
```

실행한 컴퓨터에서 영상 확인:

```text
http://127.0.0.1:8081/
```

같은 네트워크의 다른 장치에서 사용할 영상 주소:

```text
http://컴퓨터IPv4:8081/video_feed
```

단일 이미지 주소:

```text
http://컴퓨터IPv4:8081/snapshot.jpg
```

카메라를 사용하는 다른 앱을 종료하고 실행합니다. 프로그램을 실행하는 동안 영상 주소를 사용할 수 있으며, 종료는 `Ctrl+C`로 처리합니다.

### 오류 및 종료 처리

- 카메라 장치를 열지 못하면 오류를 출력하고 종료합니다.
- 프레임 읽기에 연속으로 실패하면 오류 상태를 기록합니다.
- 첫 프레임을 정해진 시간 안에 받지 못하면 실행 실패를 표시합니다.
- 종료 시 카메라 캡처를 해제하고 프레임 대기 작업에 종료를 알립니다.
- 카메라 번호·FPS·출력 포트의 입력 범위를 검사합니다.

### 환경 카메라의 YOLO 적용 범위

환경 카메라 영상에 객체 탐지를 적용할 때 본인은 다음 두 코드를 제공합니다.

- `YOLO_detector.py`: 입력 프레임 추론 및 탐지 결과 표시
- `pc_environment_camera.py`: USB 환경 카메라 연결 및 영상 제공

이 두 코드 사이의 프레임 전달, YOLO 패키지 연결 및 통합 실행 반영은 앞의 역할 구분에 따라 팀원이 담당합니다. 환경 카메라 연결 코드 자체에 객체 탐지가 구현되어 있다고 기록하지 않습니다.

## 🔵 목 관절 및 집게 제어

`SmoothServo.py`의 `SmoothNeck`은 목 관절의 위치와 조작 상태를 관리합니다.

| 부위 | 축 이름 | Servo 채널 |

| 목 A 상하 | `a_tilt` | 3 |
| 목 B 상하 | `b_tilt` | 2 |

`sync_pwm()`는 외부 동작 코드가 전달한 마지막 PWM 각도를 `SmoothNeck`의 위치 기록과 Servo 위치 캐시에 반영합니다.

이 위치는 코드가 전달한 PWM 값 기준이며, 관절의 실제 위치를 측정하는 센서값은 아닙니다.

| X / 놓기 버튼 | 집게 놓기 요청 |

`SmoothGripper`는 반복되는 유지 명령을 처리하고, 명령 갱신이 중단되면 집게를 정지시키도록 구성했습니다. 현재 유지 명령의 유효 시간은 0.9초입니다.

## 🔵 음성·텍스트 명령 처리 코드

공식 Sherpa 한국어 음성 인식 프로그램과 Claude API를 사용하여 한국어 명령을 분석하는 코드를 작성했습니다.

### 음성 입력

1. GUI에서 로봇 마이크 입력을 요청합니다.
2. 공식 Sherpa 실행 프로그램과 모델의 준비 상태를 확인합니다.
3. 준비 후 **“지금 말하시오”**를 표시합니다.
4. 로봇에 연결된 마이크에서 6초 구간의 새 전사문을 수집합니다.
5. 한국어 텍스트를 Claude API에 전달합니다.
6. 응답의 동작·시간·이유를 검사하고 동작 실행 코드에서 사용합니다.

컴퓨터·스마트폰의 내장 마이크가 아닌 **로봇에 연결된 마이크**를 사용하는 구성입니다.

### 공식 Sherpa 사용 설정

| 항목 | 설정 |
|---|---|
| 실행 프로그램 | `sherpa-onnx-alsa` |
| 공식 실행 파일 묶음 | `sherpa-onnx-v1.12.1-linux-aarch64-shared-cpu` |
| 한국어 모델 | `sherpa-onnx-streaming-zipformer-korean-2024-06-16` |
| 마이크 | `plughw:CARD=Lite,DEV=0` |
| 명령 수집 구간 | 6초 |

사용하는 모델 파일:

```text
tokens.txt
encoder-epoch-99-avg-1.int8.onnx
decoder-epoch-99-avg-1.onnx
joiner-epoch-99-avg-1.int8.onnx
```

정상 실행 중인 음성 프로세스는 다음 요청에서도 재사용합니다. 코드에서 추가 마이크 증폭·거리 제한·음량 임계값 필터를 설정하지 않습니다.

### 텍스트 입력

직접 작성한 문장은 STT를 거치지 않고 명령 분석 코드로 전달합니다.

`PiCommandPanel.py`에는 텍스트 입력창·전송·로봇 마이크·AI 중지 버튼과 처리 상태 표시를 구성했습니다.

- 음성 준비 및 남은 입력 시간 표시
- 분석 중 **“api 전달중”** 표시
- 움직이는 진행 막대
- 처리한 한국어 문장과 결과 이유 표시
- 오류 상태 표시
- 처리 중 전송·음성 버튼 비활성화

진행 막대는 대기 상태를 표현하며 API 완료율을 나타내는 퍼센트는 아닙니다.

### Claude API 분석 코드

`PiCommandCore.py`에서 API 키와 모델을 설정합니다.

```python
CLAUDE_API_KEY = "본인의 Claude API 키"
```

기본 모델명은 `claude-haiku-4-5`이며, `PICAR_CLAUDE_MODEL` 환경변수로 변경할 수 있도록 작성되어 있습니다.

API 분석 결과의 형식:

```json
{
  "command": "forward",
  "duration_ms": 2000,
  "reason": "전진 요청"
}
```

`validate_command()`에서 허용 명령·필드 구성·시간 자료형·동작별 시간 범위·설명 길이를 검사합니다. 모델 응답을 Python 코드로 실행하지 않습니다.

### 지원하도록 구성한 표현

| 입력 예시 | 분류 명령 |
|---|---|
| 앞으로 가 / 전진 / 위로 | `forward` |
| 뒤로 가 / 후진 / 아래로 | `backward` |
| 왼쪽으로 / 좌회전 | `left` |
| 오른쪽으로 / 우회전 | `right` |
| 뒤로 왼쪽으로 | `backleft` |
| 뒤로 오른쪽으로 | `backright` |
| 집게 잡아 / 집게 닫아 | `grab` |
| 집게 열어 / 집게 놓아 | `release` |
| 에이 왼쪽으로 / 에이 오른쪽으로 | `neck_a_left` / `neck_a_right` |
| 에이 위로 / 에이 아래로 | `neck_a_up` / `neck_a_down` |
| 비 위로 / 비 아래로 | `neck_b_up` / `neck_b_down` |
| 멈춰 / 정지 | `stop` |

가벼운 오타와 전사 오류는 문맥으로 해석하도록 프롬프트에 규칙을 작성했습니다. 위 표는 지원 의도를 설명하며 모든 발화의 동일한 분석 결과를 보장하지는 않습니다.

### 목 A/B 구분

- `에이/A`가 있어야 목 A 명령으로 처리합니다.
- `비/B`가 있어야 목 B 명령으로 처리합니다.
- 선택자가 없는 방향 명령은 주행으로 구분합니다.
- 목 A는 좌우·상하, 목 B는 상하만 지원합니다.
- 지원하지 않는 방향과 A/B 동시 요청은 실행하지 않도록 검사합니다.
- `A구역`·`B구역`과 다른 단어 속 문자를 목 선택자로 잘못 해석하는 것을 줄이는 검사를 포함했습니다.

### 현재 지원 범위

한 번의 요청에서 하나의 동작을 실행하는 구조입니다. 부정·모호한 명령, 여러 동작의 순차 실행, 구역 탐색·운반·거리 이동·자율주행 요청은 실행하지 않도록 규칙을 구성했습니다.

| 동작 | 기본 시간 | 최대 시간 |
|---|---:|---:|
| 전진·후진 | 2초 | 5초 |
| 회전·후진 좌우회전 | 1.5초 | 3초 |
| 집게 잡기·놓기 | 0.9초 | 1.5초 |
| 목 단일 축 | 1초 | 2초 |

`PiCommandCore.py`의 음성·텍스트 명령 속도는 주행 40, 회전 30입니다. PC GUI의 수동 조작 속도 50, 40과 설정 위치가 구분되어 있습니다.

## 🔵 로봇 카메라 및 환경 카메라 화면

### 로봇 카메라 화면

PC GUI는 전달받은 로봇 카메라 영상을 화면에 표시합니다.

- 최신 프레임 보관 및 복사
- 이미지 변환과 크기 조정
- 주기적인 화면 갱신
- 영상 갱신 상태 표시
- 전체화면에서 같은 프레임 사용

### 환경 카메라 화면

모바일 GUI에서는 환경 카메라 주소 설정 기능으로 영상 URL을 지정합니다.

- HTTP(S) MJPEG 또는 이미지 URL 입력
- 브라우저 `localStorage`에 주소 저장·복원
- 연결 중·LIVE·연결 실패·미연결 상태 표시
- 환경 카메라 전체화면

현재 `robot_gui.py`에는 환경 카메라 표시 영역이 구성되어 있습니다. 별도의 환경 카메라 스트림을 직접 수신하는 코드는 해당 파일에 포함되어 있지 않습니다. 환경 카메라 영상과 YOLO 결과를 최종 화면에 연결하는 통합 부분은 앞의 역할 구분에 따릅니다.

# 주요 코드 구성

이 문서에서 설명하는 주요 코드와 구현 부분은 다음과 같습니다.

| 파일 / 구현 부분 | 설명 |
|---|---|
| `robot_gui.py` | PC 주행·집게·후레시 조작, 카메라 표시, 상태 표시, 명령 입력 패널 연결 |
| `fullscreen_gui.py` | PC 로봇 카메라 전체화면과 주행·집게·후레시 조작 |
| `YOLO_detector.py` | YOLO 모델 호출, 프레임 추론, 박스·클래스명·신뢰도 표시 |
| `pc_environment_camera.py` | USB 환경 카메라 연결, 프레임 수집, JPEG 변환, 영상 URL 제공 |
| `OLED_eyes.py` | OLED 얼굴·눈동자·깜빡임·상태별 애니메이션 |
| `SmoothServo.py` | 목 A/B 단계 이동, 집게 유지 명령 처리, 위치 기록 동기화 |
| `PiCommandCore.py` | 공식 Sherpa 사용, 한국어 전사문 처리, Claude 명령 분석·검증·동작 실행 |
| `PiCommandPanel.py` | PC의 음성·텍스트 입력창과 명령 처리 상태 표시 |
| `GUIServer_mobile.py`의 GUI 영역 | 모바일·태블릿 화면의 HTML·CSS·JavaScript와 카메라·조이스틱·명령 입력 UI |

`GUIServer_mobile.py`는 이 문서에서 GUI 구현 부분만 설명하며, 파일 전체의 통신·통합 처리를 본인 수행 내역으로 기록하지 않습니다.
